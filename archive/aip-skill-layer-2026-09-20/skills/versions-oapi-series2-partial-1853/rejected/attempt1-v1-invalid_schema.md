```yaml
title: Pydantic v2 migration
objective: Safely migrate a Python codebase from Pydantic v1 to Pydantic v2 with explicit compatibility checks and minimal behavioral drift.
when_to_use:
  - 'Use this procedure when a project imports Pydantic v1 APIs or depends on libraries that are moving to Pydantic v2.'
  - 'Use this procedure when deprecation warnings, dependency conflicts, or framework upgrades require Pydantic v2.'
  - 'Use this procedure for either an incremental compatibility migration or a direct migration.'
inputs:
  - 'The project source tree and test suite.'
  - 'The current Python and Pydantic versions.'
  - 'Dependency manifests and lock files.'
  - 'Documented validation, serialization, schema, and settings behavior.'
  - 'Representative valid and invalid payloads for public models.'
preconditions:
  - 'Work on a dedicated branch and ensure the repository is clean.'
  - 'Record the current dependency versions and supported Python versions.'
  - 'Run the existing test suite before making changes and save the baseline result.'
  - 'Identify externally visible model behavior that must remain stable.'
  - 'Confirm whether all direct and transitive dependencies support Pydantic v2.'
procedure:
  - 'Inventory every Pydantic import, model, validator, settings class, dataclass, generic model, root model, custom type, schema hook, parsing call, serialization call, and framework integration.'
  - 'Search for deprecated APIs including parse_obj, parse_raw, parse_file, from_orm, construct, copy, dict, json, json_encoders, schema, schema_json, validate, update_forward_refs, __fields__, __fields_set__, __validators__, __root__, GenericModel, BaseSettings, validator, and root_validator.'
  - 'Classify each finding as a mechanical rename, configuration migration, validator rewrite, custom type rewrite, serialization change, settings change, framework integration, or behavior-sensitive change.'
  - 'Upgrade supporting libraries before upgrading Pydantic when those libraries publish versions compatible with both major versions.'
  - 'Choose an incremental migration when dependencies still need the Pydantic v1 interface, and temporarily import compatibility APIs from pydantic.v1 only where necessary.'
  - 'Avoid mixing Pydantic v1 and v2 model classes in the same model graph because nested compatibility behavior is not supported reliably.'
  - 'Pin Pydantic to an intentional version range during the migration so unrelated resolver changes do not obscure failures.'
  - 'Install Pydantic v2 and update the lock file in a separate dependency-focused change when repository policy permits.'
  - 'Run the official bump-pydantic codemod when appropriate, review every generated change, and never treat codemod output as proof of behavioral equivalence.'
  - 'Replace BaseModel.parse_obj with BaseModel.model_validate.'
  - 'Replace BaseModel.parse_raw and parse_file by loading the external data explicitly and then calling model_validate.'
  - 'Replace BaseModel.from_orm with model_validate and enable attribute-based input through ConfigDict with from_attributes enabled.'
  - 'Replace BaseModel.construct with BaseModel.model_construct only where intentionally bypassing validation remains safe.'
  - 'Replace model.dict calls with model_dump and review include, exclude, exclude_unset, exclude_defaults, exclude_none, and alias behavior.'
  - 'Replace model.json calls with model_dump_json and verify output formatting, Unicode handling, and custom serialization behavior.'
  - 'Replace model.copy calls with model_copy and verify whether validation is required for updated values.'
  - 'Replace schema and schema_json calls with model_json_schema and explicit JSON encoding where needed.'
  - 'Replace update_forward_refs with model_rebuild and remove unnecessary forward-reference rebuilding when postponed annotations already resolve correctly.'
  - 'Replace __fields__ access with model_fields and __fields_set__ access with model_fields_set.'
  - 'Replace class-based Config declarations with model_config assigned to ConfigDict unless a temporary compatibility layer is required.'
  - 'Translate configuration options individually rather than copying names blindly because several options were renamed, removed, or changed semantically.'
  - 'Replace orm_mode with from_attributes.'
  - 'Replace allow_population_by_field_name with populate_by_name or the current validation alias configuration supported by the pinned Pydantic version.'
  - 'Replace schema_extra with json_schema_extra.'
  - 'Replace anystr_strip_whitespace with str_strip_whitespace and migrate related string configuration names explicitly.'
  - 'Replace validate_all with validate_default and verify default-value validation through tests.'
  - 'Replace keep_untouched with ignored_types.'
  - 'Replace allow_mutation disabled behavior with frozen enabled behavior and test hashability expectations separately.'
  - 'Remove smart_union and test every affected union because Pydantic v2 uses different union selection behavior.'
  - 'Remove fields configuration and express field-specific metadata with Field declarations, Annotated metadata, aliases, validators, or serializers.'
  - 'Review extra-field handling, assignment validation, arbitrary type support, protected namespaces, strictness, alias handling, and serialization configuration.'
  - 'Replace validator with field_validator and select before, after, wrap, or plain mode based on the original intent.'
  - 'Replace root_validator with model_validator and select before, after, or wrap mode based on whether validation needs raw input or a model instance.'
  - 'Remove unsupported validator keyword arguments and obtain field or configuration details through the validation info object.'
  - 'Do not rely on TypeError raised inside validators being converted into ValidationError because Pydantic v2 exposes TypeError directly.'
  - 'Review whether validators must run for defaults and use validate_default or appropriate validator configuration instead of assuming always has identical semantics.'
  - 'Ensure model-level after validators return the validated model instance.'
  - 'Review assignment validation because model validators may receive an existing instance rather than a raw mapping.'
  - 'Replace each __root__ model with RootModel and update construction, validation, serialization, iteration, and schema tests.'
  - 'Replace GenericModel inheritance with BaseModel plus Generic and verify parameterized generic usage.'
  - 'Avoid using parameterized generic aliases directly in isinstance checks and create named subclasses when runtime checks are required.'
  - 'Migrate constrained types toward Annotated metadata and constraints when this improves compatibility and static analysis.'
  - 'Review Field arguments and replace removed or renamed options such as regex with pattern and const with Literal.'
  - 'Move reusable item constraints into Annotated element types because container constraints are not always propagated to contained values.'
  - 'Review Optional fields carefully because an Optional annotation does not by itself imply a default value of None.'
  - 'Review nullable, required, and default semantics for every public field and compare generated JSON Schema with the baseline.'
  - 'Review numeric, string, iterable, mapping, and union coercion because Pydantic v2 intentionally changes several coercion rules.'
  - 'Use strict mode or strict field types where the contract must reject coercion rather than relying on historical behavior.'
  - 'Replace json_encoders with field_serializer, model_serializer, computed_field, or supported type-level serialization hooks.'
  - 'Verify that subclass fields are serialized intentionally because nested subclass serialization is safer and more restrictive in Pydantic v2.'
  - 'Review model equality assumptions because models are no longer equal to dictionaries and equality includes additional model state.'
  - 'Review private attributes because they participate in model equality and have updated internal behavior.'
  - 'Replace custom __get_validators__ implementations with core schema hooks when maintaining custom types.'
  - 'Replace __modify_schema__ with __get_pydantic_json_schema__ and use the provided schema handler rather than mutating unsupported internal structures.'
  - 'Use TypeAdapter for validating or serializing non-model types, dataclasses, typed dictionaries, unions, and annotated types.'
  - 'Review Pydantic dataclasses because validation timing, extra handling, tuple input, and access to model internals differ in Pydantic v2.'
  - 'Replace BaseSettings imports from pydantic with BaseSettings from pydantic-settings.'
  - 'Install pydantic-settings explicitly and migrate settings configuration, environment prefixes, aliases, nested delimiters, case sensitivity, secrets directories, and source customization.'
  - 'Review settings source precedence and environment parsing with isolated tests rather than assuming Pydantic v1 ordering.'
  - 'Replace moved network or payment validation extras with explicit dependencies such as email-validator when required.'
  - 'Update FastAPI, SQLModel, Django integrations, command-line frameworks, and other model consumers to versions that support the selected Pydantic version.'
  - 'Check framework-specific request parsing, response serialization, OpenAPI generation, dependency injection, ORM loading, and error response behavior.'
  - 'Update type-checker plugins and configuration for mypy, Pyright, Ruff, and other static analysis tools.'
  - 'Regenerate generated clients, OpenAPI artifacts, JSON Schema snapshots, and documentation only after contract changes have been reviewed.'
  - 'Run formatting, linting, static type checking, unit tests, integration tests, and packaging checks after each migration group.'
  - 'Add regression tests for every intentional or unavoidable behavior change discovered during migration.'
  - 'Remove temporary pydantic.v1 imports after all dependencies and model graphs use Pydantic v2.'
  - 'Remove obsolete compatibility pins, suppressions, and migration comments only after the full validation matrix passes.'
validation:
  - 'The supported Python version matrix installs successfully from a clean environment.'
  - 'No unintended imports remain from pydantic.v1.'
  - 'No deprecated Pydantic v1 APIs remain unless they are documented temporary exceptions.'
  - 'All valid representative inputs still validate to the expected values and types.'
  - 'All invalid representative inputs still fail at the intended fields with acceptable error categories.'
  - 'Model dumps and JSON output preserve documented aliases, exclusions, defaults, null handling, and custom representations.'
  - 'JSON Schema and OpenAPI differences are either absent or explicitly reviewed and approved.'
  - 'Settings tests confirm source precedence, environment parsing, aliases, nested values, secrets, and defaults.'
  - 'ORM and attribute-based validation tests pass for representative application objects.'
  - 'Framework request, response, and error-handling integration tests pass.'
  - 'Static type checking, linting, unit tests, integration tests, and packaging checks pass.'
  - 'The dependency resolver reports no incompatible Pydantic constraints.'
common_pitfalls:
  - 'Do not assume renamed methods are behaviorally identical without contract tests.'
  - 'Do not mix Pydantic v1 and v2 models inside fields, unions, generics, dataclasses, or settings structures.'
  - 'Do not preserve obsolete configuration options merely because they do not immediately raise errors.'
  - 'Do not assume Optional means a field is not required.'
  - 'Do not assume all Pydantic v1 input coercions remain available.'
  - 'Do not assume TypeError in a validator becomes ValidationError.'
  - 'Do not mutate unsupported core schema structures directly.'
  - 'Do not expose schema or serialization changes without reviewing downstream consumers.'
  - 'Do not remove dependency pins until every supported environment has been tested.'
rollback:
  - 'Revert the migration changes and restore the previous dependency lock file if production-critical behavior cannot be preserved safely.'
  - 'If an incremental migration is required, isolate remaining Pydantic v1 code behind pydantic.v1 imports and document its removal condition.'
  - 'Keep data migrations separate from library migration changes so application data can be rolled back independently.'
completion_criteria:
  - 'The project runs on the selected Pydantic v2 release without unintended Pydantic v1 compatibility imports.'
  - 'All required automated checks pass in clean environments.'
  - 'Validation, serialization, schema, settings, and integration contracts are verified.'
  - 'Every intentional behavior change is documented with a regression test.'
  - 'Temporary compatibility code has an owner and a removal plan.'
```
